# Implementation Workstreams

> **Status:** Standalone major-update specification — not yet merged into the authoritative Koali/kOA documentation.  
> **Baseline reviewed:** 2026-09-09 snapshots of Koali Spaces, Koali Control Panel, kOA Linux, LevelUpDiag, parallel design plans, and the Senior Architecture Patterns reference.  
> **Authority rule:** Until this package is explicitly adopted, existing repository documentation and contracts remain authoritative. This package defines the proposed target and the delta to close.

Workstreams are parallel ownership domains, not sequential product phases.

| ID | Workstream | Primary authority |
|---|---|---|
| WS-A | governance, contracts, compatibility | Koali Spaces + kOA Linux |
| WS-B | appearance/preferences and design tokens | Koali Spaces |
| WS-C | shell/Home/global UX | Koali Spaces |
| WS-D | GlobalProjectionRuntime and resilience | Koali Spaces |
| WS-E | hosted onboarding and SpaceActivationCompiler | Koali Spaces |
| WS-F | Konnaxion/Médiathèque/Orgo conformance packages | owner repos + Koali |
| WS-G | Native Workspace admission/session/substrate | kOA Linux |
| WS-H | native projection and launcher UX | Koali Spaces + kOA Linux |
| WS-I | native security/resource/data/release | kOA Linux |
| WS-J | Development Environment / DevPad | Control Panel / DevPad |
| WS-K | observability/conformance/LevelUpDiag | owning repos + LevelUpDiag where delegated |
| WS-L | distributed/VPS qualification | operations + owner services |

A workstream may proceed whenever its owning contract is sufficiently defined. No workstream is called a 'phase'.
